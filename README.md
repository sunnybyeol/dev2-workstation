# Mini NPU Simulator

작은 NPU가 입력 패턴과 필터를 같은 위치끼리 곱하고 모두 더하는 MAC(Multiply-Accumulate) 계산을 흉내 내는 Python 콘솔 프로그램입니다. 계산 결과가 더 큰 필터의 모양을 패턴의 종류로 판정합니다.

## 실행 환경과 시작

- Python 3.8 이상, 표준 라이브러리만 사용합니다. NumPy 설치는 필요하지 않습니다.
- PowerShell에서 `Set-Location C:\dev\dev2-workstation` 후 `python main.py`를 실행합니다. Python 런처가 설정된 환경에서는 `py -3 main.py`도 사용할 수 있습니다.
- `data.json`은 `main.py`와 같은 폴더에 둡니다. `C:\Users\witch\Downloads\data.json`을 적용했으며, 5·13·25 크기의 사례 6건을 포함합니다. 숫자 0/1로 된 입력 패턴과 유한한 실수 가중치를 가진 필터를 지원합니다.

## 메뉴

1. **사용자 입력**: 3×3 필터 A/B와 패턴을 입력하고 각 점수와 판정을 봅니다. 각 행에는 공백으로 구분한 0 또는 1 세 개를 입력합니다.
2. **JSON 분석**: `data.json`의 모든 사례를 검증하고 PASS/FAIL과 실패 이유, 크기별 성능을 출력합니다.
3. **보너스**: N을 입력해 Cross 또는 X 패턴을 자동 생성하고 2D/1D 성능을 비교합니다.
4. **종료**

입력 예외 예: 크기가 3인 행에 `1 0` 또는 `1 a 0`을 입력하면 형식을 안내하고 그 행을 다시 요청합니다. 메뉴에서 `abc`를 입력하면 정수를 요구하고, 허용 범위 밖 숫자에는 범위를 알려줍니다. Ctrl+C 또는 입력 종료(EOF)에는 안전 종료 메시지를 표시합니다.

## MAC 계산과 판정

크기 N의 패턴 `P`와 필터 `F`에 대해 `score = Σ(P[i][j] × F[i][j])`를 계산합니다. 각 필터는 N²회의 곱셈 누산을 수행하며, Cross와 X 두 필터를 비교하면 사례 하나당 2N² MAC 위치를 방문합니다. 점수가 클수록 해당 필터 모양과 더 잘 맞습니다. 점수 차이의 절댓값이 `1e-9`보다 작으면 순서에 상관없이 `UNDECIDED`로 처리합니다. JSON의 `+`, `십자`는 Cross로, `x`, `×`는 X로 통일한 뒤 비교합니다.

`data.json` 구조는 `filters.size_5.cross`, `filters.size_5.x`처럼 크기별 필터를 두고, `patterns.size_5_1` 아래에 `input` 2차원 배열과 `expected` 레이블을 둡니다. 입력 패턴은 이진값이어야 하며 필터 가중치는 유한한 숫자를 허용합니다. 전달된 파일에서 계산상 동점인 세 사례는 기존 `x`/`+` 예상값과 모순되어 `UNDECIDED`로 바로잡았습니다. 크기·행·열·값·키·레이블이 맞지 않는 사례는 프로그램을 중단하지 않고 해당 사례만 FAIL 처리하며 이유를 기록합니다.

## 설계와 성능

`main.py`는 메뉴, 입력 검증, 출력 흐름을 맡습니다. `npu_sim.py`는 입력 데이터에 부작용 없이 MAC·레이블 판정·유효성 검증·벤치마크를 수행하며, `storage`나 외부 서비스는 사용하지 않습니다. `Quiz`처럼 상태와 동작이 함께 있는 객체를 만들기보다 이 미션의 행렬 계산은 독립 함수로 두어 작은 순수 계산 단위로 검증하기 쉽도록 했습니다.

주요 연결: `read_matrix`가 사용자 행을 검증하고, `compare_manual`이 두 점수와 판정을 위임받습니다. `evaluate_dataset`은 각 JSON 사례를 격리해 처리하고 `benchmark_by_size`가 유효 사례에 한해 성능을 측정합니다. `generate_pattern`과 `generate_standard_filters`는 보너스 자동 생성 및 벤치마크에 재사용됩니다.

복잡도는 N×N 모든 위치를 한 번씩 방문하므로 필터 한 개당 시간 O(N²), 입력 행렬 저장 공간 O(N²)입니다. 두 필터 비교 역시 상수 배수만 달라 O(N²)입니다.

### 보너스 1: 1차원 배열 최적화 비교

기준 구현 `mac_2d`는 행/열 인덱스로 중첩 리스트를 읽습니다. 보너스 구현 `flatten`은 timed loop 바깥에서 행렬을 1차원 리스트로 펼치고, `mac_flat`은 한 인덱스 루프로 순회합니다. 벤치마크는 크기별 10회 이상 반복, 검증·JSON 읽기·flatten 시간 제외, 사례당 평균(ms)을 출력하며 두 구현의 점수 일치도 먼저 확인합니다. 단순 Python 환경의 실행시간은 시스템 부하에 따라 달라질 수 있고, 1D가 항상 더 빠르다고 보장하지 않습니다.

### 보너스 2: 자동 패턴 생성

메뉴 3에서 N(1~25)과 종류를 선택하면 정사각형 Cross/X 패턴을 만들고 표준 필터와 비교합니다. 짝수 N은 중앙 두 행/열을 사용해 패턴이 대칭을 유지합니다.

## 원인 분석 및 오류 대응

1. 사용자 행의 길이를 검사하지 않으면 인덱스 오류가 나거나 잘못된 점수가 계산됩니다.
2. 그래서 입력 행마다 정확히 N개인지 확인하고, 틀린 행만 다시 받습니다.
3. `int()` 변환 실패는 `ValueError`이므로 숫자가 아닌 토큰을 별도로 안내합니다.
4. 입력 패턴 값이 0/1 이외이면 이진 행렬이라는 계산 가정을 어기므로 거부합니다. 필터는 실수 가중치를 허용하되 NaN·무한대는 거부합니다.
5. JSON 키의 크기와 실제 입력 크기가 다르면 인덱싱 오류가 발생할 수 있습니다.
6. 크기는 `size_N_idx`에서 읽되, 행렬의 행·열도 같은 N인지 별도로 검증합니다.
7. 필터가 없거나 Cross/X 중 하나가 빠진 경우 해당 케이스에 원인을 남깁니다.
8. 잘못된 JSON 한 건 때문에 나머지 사례까지 검사하지 못하는 문제를 막기 위해 사례별 예외 처리를 적용했습니다.
9. 예상 레이블은 alias를 정규화한 뒤 계산 결과와 비교하여 대소문자나 `+`/`Cross` 표기 차이를 제거합니다.
10. 부동소수점의 아주 작은 차이가 임의 판정으로 이어지지 않게 epsilon 동점 규칙을 사용합니다.
11. 벤치마크에 파일 읽기나 행렬 변환을 포함하면 MAC 자체 성능과 구분할 수 없어 측정 구간 밖에서 준비합니다.
12. 반복 횟수가 너무 적으면 타이머 오차 비중이 커서 최소 10회로 고정했습니다.
13. 1D 루프가 빨라지는지는 Python 버전과 시스템에 따라 다르므로 실제 측정치와 점수 일치를 함께 기록합니다.
14. JSON은 사람이 확인하고 수정하기 쉬우며 다른 환경에서도 읽을 수 있어 작은 고정 예제에 적합합니다.
15. 사례가 매우 커지면 전체 JSON을 메모리에 올리는 방식은 메모리와 수정 충돌에 불리합니다. 대량 데이터는 SQLite 같은 DB, 줄 단위 NDJSON/스트리밍 처리를 고려합니다.
